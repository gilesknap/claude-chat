Every layer a conversion has to touch

  1. configure/RELEASE
    Drops GENSUB = $(SUPPORT)/genSub/1-8dls3
  2. etc/builder.py
    Drops from iocbuilder.modules.genSub import *, and removes genSub from Dependencies
  3. userIOApp/Db/movingAverage.vdb
    record(genSub, "$(P):CALCMOVINGAV") becomes record(aSub, …) — and the macro comments get rewritten into msi # % macro, form
  4. userIOApp/src/userIOSupport.dbd
    registrar("movingAverage") becomes function(initAverage) and function(calcAverage)
  5. userIOApp/src/movingAverage.c
    −33 lines: the genSub registrar boilerplate goes away, and the routines become plain epicsRegisterFunction targets

The dbd line is the bit worth remembering.

genSub needed a registrar to publish the routine. aSub uses base’s own function() declarations, and SNAM then resolves natively.

Caveat relevant to this repo

Converting doesn’t make a module vendorable

As .claude/skills/streamdevice-sweep/SKILL.md:333 notes, a genSub → aSub conversion does not make a support module vendorable as a runtime pattern.

The routine is still C, compiled into the module’s own library, either way. The record type changed; the build-time dependency did not.
